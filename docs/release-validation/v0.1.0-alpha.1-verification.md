## Fresh-clone Quick Start

Cloned into a clean directory (not this working tree), no reused `.venv`, Neo4j volumes, or
untracked files:

```bash
git clone https://github.com/michaelegner/architecture-intelligence-platform.git
cd architecture-intelligence-platform
docker compose up --build
```

- `GET /health` → `{"status":"ok"}`
- `GET /health/neo4j` → `{"status":"ok"}`
- `POST /api/import` → 200, imported all four fixture services
- A deterministic analysis (`GET /api/analysis/queues/without-consumers`) → 200 with the expected
  `unused-q` result
- `POST /api/query` with `"Who sends to payment-q?"` → routes deterministically, no LLM key needed
- `POST /api/query` with an unrecognized question and no `OPENAI_API_KEY` set → graceful `503`
  ("LLM query subsystem is not configured"), not a crash

**Found and fixed during this run**: `docker-compose.yml` used `${OPENAI_API_KEY:?...}` (hard
required), contradicting the documented LLM-optional guarantee — a fresh clone with a blank
`OPENAI_API_KEY` (as `.env.example` specified at the time) failed to start at all. Fixed to
`${OPENAI_API_KEY:-}`.

## Fresh-clone runtime demo

Same clean clone, `docker compose -f docker-compose.demo.yml up --build`, then
`examples/runtime-demo/README.md`'s walkthrough followed exactly:

- Immediately after `POST /api/import`, before any traffic: every declared relation showed
  `NOT_OBSERVED_IN_WINDOW` (`GET /api/analysis/runtime/declared-only?environment=demo`).
- After traffic landed: `order-service → product-service.getProduct` and the `payment-q`/
  `invoice-q` sends/receives showed `CONFIRMED`.
- `OrderService → LegacyPricingService` (never declared anywhere) showed `OBSERVED_ONLY`.
- The 11H reconciliation scenario: removed `order-service`'s `calls` entry, reimported just that
  service, watched `product-service` move from `confirmed` to `observed-only` (not deleted) —
  confirmed via the real API, then restored the fixture.
- Cross-batch correlation: watched the traffic generator's log lines showing a CLIENT span and its
  matching SERVER span sent as two separate OTLP requests, still resolving to one relation.
- The web UI (`/services/service:order-service`, `/query`) shows the same states.

**Found and fixed during this run**: the natural-language query page (and any O1-O5 API call
without an explicit `environment` param) silently returned zero rows against demo data, because
`config.yaml`'s `runtime_analysis.default_environment` (`production`) didn't match the demo's own
`environment=demo` traffic tag. Fixed with a demo-specific `config.demo.yaml`
(`docker-compose.demo.yml`'s `CONFIG_PATH`).

## GHCR image — pulled and run from a clean environment

```bash
docker pull ghcr.io/michaelegner/architecture-intelligence-platform:v0.1.0-alpha.1
```

Run against a freshly-started Neo4j container (no local source checkout involved at all — just the
published image): container starts, connects to Neo4j, `GET /health` and `GET /health/neo4j` both
return `200`.

**Confirmed genuinely public**, not just API-reported: `docker logout ghcr.io`, deleted the local
image, pulled again with **zero credentials** — succeeded. `:latest` and `:v0.1.0-alpha.1` resolve
to the identical digest above.

**Found and fixed during this run**: the container ran as `root` (`docker exec ... id` →
`uid=0(root)`) — no `USER` instruction in `Dockerfile`. Fixed: dedicated `app` user (uid/gid 1000),
`COPY --chown`, `USER app` before `CMD`. Re-verified end-to-end after the fix — `docker exec ...
whoami` → `app` — both standalone and via `docker-compose.demo.yml` (which bind-mounts
`examples/` and `config.demo.yaml` from the host; host-owned files stayed readable to the non-root
user under standard world-readable permissions, no breakage).
